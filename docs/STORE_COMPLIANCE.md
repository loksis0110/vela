# Публикация в магазинах: что уже сделано и что сделать вам

## App Store (iPhone)

Уже в проекте:

- [x] VPN работает через Network Extension (`NEPacketTunnelProvider` / `NETunnelProviderManager`), как требует правило 5.4.
- [x] Приложение не собирает данные, нет рекламы и трекинга. Файлы `PrivacyInfo.xcprivacy` в приложении и расширении.
- [x] Ключи и подписки исключены из резервных копий и защищены файловой защитой iOS.
- [x] Пользователь видит системный запрос на добавление VPN-конфигурации, без обходных путей.
- [x] В приложении нет встроенных серверов и обхода блокировок «из коробки»: это клиент для серверов пользователя.
- [x] Уведомления (напоминания об окончании подписки и трафика) локальные, без push-сервера. Разрешение iOS спрашивает системным окном; без него приложение работает, просто без напоминаний.
- [x] Буфер обмена читается только когда приложение на экране, текст проверяется на устройстве и никуда не отправляется. С iOS 16 система сама показывает запрос «Разрешить вставку», пользователь может запретить вставку в Настройках iOS → Vela. Это описано в `PRIVACY.md`.

Сделать вам:

- [ ] **Схемы ссылок.** Кроме `vela://` приложение регистрирует схемы других клиентов (`happ`, `v2rayng`, `hiddify`, `sing-box`, `clash`, `streisand` и другие), чтобы открывать кнопки «Добавить подписку» с сайтов провайдеров. Если такую же схему зарегистрировало другое установленное приложение, iOS сама выбирает, какое открыть. Прямого запрета в правилах App Store нет, но проверяющий может посчитать чужие схемы подражанием другим приложениям. Если отклонят, оставьте в сборке для App Store только `vela` и `sub`.
- [ ] **Аккаунт разработчика как организация** ($99/год). Для VPN аккаунт физлица не подойдёт (правило 5.4).
- [ ] Свой Bundle ID и App Group в `ios/project.yml`, затем `xcodegen`.
- [ ] В App Store Connect: опубликуйте политику конфиденциальности (`PRIVACY.md`) по публичной ссылке, в разделе App Privacy выберите «Data Not Collected». HWID уходит только провайдеру, которого добавил пользователь, а не вам и не вашим партнёрам; Apple считает «сбором» доступ разработчика или его партнёров. Если сомневаетесь, отметьте «Device ID» как необязательный и не связанный с личностью.
- [ ] **Тестовый сервер для проверки.** В Notes for Review дайте рабочую ссылку на подписку: без неё ревьюер не сможет подключиться и отклонит приложение.
- [ ] Экспортный контроль: приложение использует стандартное шифрование (TLS, QUIC) через ядро. В App Store Connect ответьте, что используется шифрование, подпадающее под исключения для массового рынка. Ключ `ITSAppUsesNonExemptEncryption` уже задан.
- [ ] В описании не обещайте «обход блокировок» и не упоминайте конкретные заблокированные сервисы. Описывайте как клиент для подключения к своим серверам по протоколам VLESS, Trojan, Hysteria2.
- [ ] Выберите страны распространения. В российском App Store VPN-приложения удаляют по требованию Роскомнадзора, планируйте другие регионы.
- [ ] Лицензия GPL-3.0: откройте исходный код той версии, которую публикуете, и дайте на него ссылку в описании. Учтите, что совместимость GPL с условиями App Store спорна. Для закрытого коммерческого продукта ядро лучше заменить на Xray-core (MPL-2.0).

## Google Play (Android)

Уже в проекте:

- [x] `VpnService` используется только для основной функции, трафик шифруется до сервера пользователя.
- [x] Тип foreground-сервиса `systemExempted`, разрешённый для VPN-приложений. Постоянное уведомление с кнопкой «Отключить».
- [x] Нет рекламы, аналитики и запроса лишних разрешений: ни геолокации, ни списка приложений, ни контактов.
- [x] Данные исключены из облачных резервных копий (`data_extraction_rules.xml`).
- [x] Target SDK 37, сборка App Bundle (`.aab`) в CI.
- [x] **Отдельная сборка `play`** (`Vela-1.4.0-play.aab`): переключатель блокировки рекламы скрыт и принудительно выключен. Декларация VpnService прямо предупреждает: «Any manipulation of ads that can impact monetization will result in rejection». Сборка `full` (APK для сайта) блокировку рекламы сохраняет.
- [x] Разрешение на уведомления (`POST_NOTIFICATIONS`, Android 13+) запрашивается у пользователя. Без него VPN работает, но не будет напоминаний об окончании подписки и трафика.
- [x] Буфер обмена: Android 10+ даёт читать его только приложению на экране, Android 12+ показывает всплывающее «Vela: вставлено из буфера обмена». Текст проверяется на устройстве и никуда не отправляется, это сказано в `PRIVACY.md`.
- [x] Схемы ссылок (`vela` и схемы других клиентов) только открывают окно подтверждения «Добавить подписку …?». Без подтверждения ничего не добавляется и не скачивается.
- [x] Список приложений для раздельного туннелирования берётся через `<queries>` (только приложения со значком), без ограниченного разрешения `QUERY_ALL_PACKAGES`.

Сделать вам (подробно по шагам: [google-play/GUIDE.md](google-play/GUIDE.md)):

- [ ] Аккаунт Google Play Console ($25 один раз). **Для приложений с `VpnService` Google требует аккаунт организации** (D-U-N-S). Для новых личных аккаунтов действует обязательное закрытое тестирование: 12 тестировщиков 14 дней подряд.
- [ ] Загружайте в Play только `Vela-1.4.0-play.aab`, не APK сборки `full`.
- [ ] Свой `applicationId` в `android/app/build.gradle.kts` и **ключ подписи**: создайте keystore и добавьте его в секреты GitHub (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`). Потеряете ключ — не сможете выпускать обновления.
- [ ] В Play Console заполните декларацию **VpnService** ([google-play/vpn-declaration.md](google-play/vpn-declaration.md), нужно видео до 90 секунд) и декларацию типа foreground-сервиса, если её спросят.
- [ ] Data safety по [google-play/data-safety.md](google-play/data-safety.md). Из-за HWID ответ не «ничего не собирается», а «собирается необязательно: идентификатор устройства». Ссылка на политику конфиденциальности должна быть публичной.
- [ ] Тексты страницы: [google-play/listing-ru.md](google-play/listing-ru.md), [google-play/listing-en.md](google-play/listing-en.md). В описании должно быть сказано, что приложение использует VpnService.
- [ ] Тестовая подписка в разделе App access для проверяющих.
- [ ] Возрастной рейтинг: анкета IARC.
- [ ] Не используйте в названии и описании чужие бренды: Happ, sing-box, v2ray, названия заблокированных сервисов.
- [ ] Распространение по странам: РКН регулярно требует от Google удалить VPN-приложения из российского Play. Google в основном не выполняет требования и платит штрафы, но удаление из российского магазина возможно в любой момент. Для РФ держите APK на своём сайте, в RuStore или F-Droid.

## Windows

- [ ] Подпишите `Vela.exe` сертификатом подписи кода (OV или EV), иначе SmartScreen будет предупреждать пользователей.
- [ ] Для Microsoft Store упакуйте в MSIX. VPN с TUN-адаптером требует прав администратора, проверьте политику Store для таких приложений.

## Юридические вопросы для РФ

Распространять VPN-клиент в России законно, но с 2024 года запрещена реклама и популяризация средств обхода блокировок.
Формулируйте описание нейтрально. Это не юридическая консультация: перед коммерческим запуском проконсультируйтесь с юристом.
